# نیکا — سامانه مدیریت مجتمع مسکونی (نسخه ۰.۲)

برنامه‌ی وب موبایل‌محور (PWA) روی **Cloudflare Workers + D1**، بدون نیاز به R2 یا سرویس ذخیره‌سازی ابری جداگانه.

## امکانات و صفحه‌ها (همه به API وصل‌اند)

| بخش | کاری که می‌کند | API |
|---|---|---|
| ورود | ورود ساکن/مالک (واحد + موبایل + رمز) یا مدیر/کارکنان (موبایل + رمز)؛ تغییر رمز اجباری در اولین ورود؛ بازیابی نشست با رفرش | `/api/login` `/api/me` `/api/password` `/api/logout` |
| خانه | نمودار هزینه‌ها و وصول شارژ هر ماه، آخرین اطلاعیه | `/api/dashboard` `/api/notices` |
| مقررات / مصوبات / تقویم / اسناد | محتوای واقعی از دیتابیس؛ تقویم شمسی با رویدادها | `/api/rules` `/api/resolutions` `/api/events` `/api/documents` |
| درخواست و پیشنهاد | ثبت، پیگیری وضعیت و پاسخ مدیریت؛ «نمایش در تابلو» | `/api/requests` |
| امکانات | گزارش خرابی که به درخواست تبدیل می‌شود | `/api/requests` |
| مالی | مانده‌ی واحد، ثبت پرداخت و رسید، تراکنش‌ها، لغو پرداخت در انتظار | `/api/finance/my` `/api/transactions` |
| پیام‌ها | پیام به مدیریت، پاسخ مدیر (و پاسخ خودکار به درخواست‌ها)، نشان خوانده‌نشده | `/api/messages` `/api/summary` |
| حساب من | پروفایل، ویرایش، تصویر (کوچک‌شده در مرورگر)، تغییر رمز، خروج | `/api/profile` `/api/avatar` |
| مدیریت (برای نقش‌های مدیریتی، بر اساس مجوز) | کاربران، واحدها، تعریف شارژ، تأیید پرداخت/هزینه، مانده‌ی واحدها، درخواست‌ها، پیام‌ها، اطلاعیه‌ها، محتوا، ممیزی | `/api/admin/*` `/api/finance/*` |

### مسیر یک پرداخت (ارتباط بین صفحه‌ها)
مدیر مالی «شارژ» را برای واحدها تعریف می‌کند ← ساکن در **مالی** مانده را می‌بیند و «ثبت پرداخت» می‌زند ← پرداخت «در انتظار تأیید» است ← مدیر مالی در **مدیریت ← مالی** تأیید یا (با ذکر دلیل) رد می‌کند ← مانده‌ی واحد و نمودار **خانه** به‌روز می‌شود. هزینه‌ها: مدیر اجرایی ثبت می‌کند ← مدیر مالی تأیید می‌کند ← در نمودار هزینه‌های خانه می‌آید.

## استقرار

```bash
npm install
npx wrangler d1 create nika-db            # database_id را در wrangler.toml جایگزین کنید
npm run migrate:remote                    # اجرای migrations/0001 و 0002 (روی دیتابیس موجود هم امن است)
npx wrangler secret put JWT_SECRET        # رشته‌ی تصادفی حداقل ۳۲ کاراکتر
npx wrangler secret put BOOTSTRAP_KEY     # کلید یک‌بارمصرف راه‌اندازی
npm run deploy
```

اگر مخزن را از طریق GitHub به Cloudflare وصل کرده‌اید، دو Secret بالا را در داشبورد (Settings ← Variables and Secrets) بسازید و `migrate:remote` را یک‌بار از کامپیوتر خود اجرا کنید.

**ساخت مدیر اصلی** (فقط یک‌بار؛ بعد از اولین کاربر خودکار بسته می‌شود):

```bash
curl -X POST https://YOUR-DOMAIN/api/setup \
  -H "Content-Type: application/json" -H "X-Setup-Key: <BOOTSTRAP_KEY>" \
  -d '{"name":"نام رئیس","phone":"09121234567","password":"یک رمز قوی حداقل ۱۰ کاراکتری"}'
```
سپس در صفحه‌ی ورود، نوع حساب را «مدیر / کارکنان» بگذارید و وارد شوید. از **مدیریت ← کاربران** حساب‌های دیگر را بسازید؛ رمز موقت تصادفی فقط یک‌بار نمایش داده می‌شود.

> **اگر قبلاً نسخه‌ی قدیمی را راه‌اندازی کرده‌اید:** رمزها با ۲۱۰٬۰۰۰ تکرار PBKDF2 ساخته شده بودند که Workers نمی‌پذیرد. ساده‌ترین راه: دیتابیس را خالی کنید و دوباره `/api/setup` بزنید، یا برای هر کاربر «بازنشانی رمز» بزنید.

### فونت
برای اینکه به Google Fonts وابسته نباشد، فونت داخل پروژه بارگذاری می‌شود. فایل `Vazirmatn.woff2` را در `public/assets/fonts/` بگذارید و در `public/app.css` کامنت خط `@font-face` را بردارید. تا آن زمان از فونت‌های سیستم (Tahoma) استفاده می‌شود.

## نقش‌ها و مجوزها
| نقش | دسترسی |
|---|---|
| مالک / ساکن | مشاهده و پرداخت در صندوق خودش (مالکانه / شارژ ماهیانه)، ثبت درخواست و پیام |
| مدیر اجرایی | ثبت هزینه، رسیدگی به درخواست‌ها |
| مدیر مالی | تعریف شارژ، تأیید/رد پرداخت و هزینه، گزارش مانده‌ها |
| هیأت‌مدیره | مشاهده‌ی گزارش‌های تجمیعی، مدیریت مصوبات |
| مدیر ساختمان | کاربران (فقط ساکن/مالک/مدیر اجرایی)، واحدها، اطلاعیه‌ها، پیام‌ها، محتوا |
| رئیس | همه چیز + نقش‌ها + ممیزی |

هر نفر می‌تواند چند نقش داشته باشد. مالک و ساکن یک واحد حساب‌های جدا دارند. فقط «رئیس» می‌تواند نقش‌های رئیس/مالی/هیأت‌مدیره/مدیر ساختمان بدهد.

## امنیت (آنچه اصلاح شد)
- ورود مدیر/کارکنان بدون شماره واحد کار می‌کند؛ رمز دیگر برابر موبایل نیست (رمز موقت تصادفی + تغییر اجباری **سمت سرور**).
- نشست در کوکی `HttpOnly; SameSite=Strict; Secure` است، نه `localStorage`؛ XSS نمی‌تواند توکن را بدزدد. هدر `X-Nika-Client` و بررسی `Origin` جلوی CSRF را می‌گیرد.
- همه‌ی داده‌های کاربر در رابط escape می‌شوند و CSP سخت‌گیرانه (`script-src 'self'`) در `public/_headers` فعال است.
- `building_admin` دیگر همه‌کاره نیست و نمی‌تواند رئیس یا مدیر مالی بسازد/تغییر دهد؛ آخرین رئیس قابل غیرفعال‌سازی نیست.
- محدودیت تلاش ناموفق ورود (۵ بار در ۱۵ دقیقه برای هر حساب، ۳۰ بار برای هر IP)، مقایسه‌ی زمان‌ثابت، PBKDF2 با ۱۰۰٬۰۰۰ تکرار (حداکثر مجاز Workers).
- تغییر رمز نیاز به رمز فعلی دارد و نشست‌های دیگر را می‌بندد؛ تغییر موبایل هم رمز می‌خواهد و تکراری‌بودن را بررسی می‌کند.
- مالی: ساکن فقط «پرداخت» می‌سازد؛ شارژ/اعتبار فقط مدیر مالی؛ ثبت‌کننده نمی‌تواند مورد خودش را تأیید کند (`ALLOW_SELF_APPROVAL` برای ساختمان‌های خیلی کوچک)؛ هزینه‌ها و دلیل ردها ثبت می‌شود.
- همه‌ی عملیات حساس در `audit_logs` ثبت و فقط برای رئیس قابل مشاهده است.

## محدودیت‌های فعلی
- **پرداخت آنلاین** وصل نیست؛ پرداخت به‌صورت «ثبت رسید + تأیید مدیر مالی» است. اتصال درگاه (زرین‌پال، آی‌دی‌پی و…) یک افزونه‌ی بعدی است.
- اعلان پوش/پیامک و ورود با OTP ندارد. تصاویر پیوست درخواست هزینه موقتاً در D1 ذخیره می‌شوند و از بخش «پشتیبان‌گیری» می‌توان فایل آرشیو آفلاین تهیه کرد. پس از دانلود و تأیید checksum، فقط داده تصویری پیوست‌ها پاک می‌شود و ردیف‌ها و تمام سوابق مالی/مدیریتی باقی می‌مانند.
- تصویر پروفایل (حداکثر ۲۰۰ کیلوبایت) در D1 ذخیره می‌شود؛ برای مقیاس بزرگ‌تر R2 بهتر است.
- «اسناد» پیوند خارجی (https) هستند، نه فایل بارگذاری‌شده.

## بایگانی آفلاین و پشتیبان ماهانه
- از پنل مدیریت ← «پشتیبان‌گیری»، فایل JSON آرشیو شامل جداول عملیاتی ساختمان و تصاویر پیوستِ هنوز آنلاین دانلود می‌شود.
- فایل شامل هش رمز عبور یا نشست ورود نیست؛ برای حفاظت از اطلاعات مالی و شخصی، آن را در رایانه امن و یک حافظه جداگانه نگه دارید.
- مرورگر SHA-256 فایل را بررسی می‌کند. فقط پس از دانلود و تأیید دستی ذخیره فایل، سامانه تصویرهای پیوست‌شده را از D1 پاک می‌کند.
- فقط محتوای تصویری پیوست‌ها پاک می‌شود؛ ردیف‌های اسناد، مبالغ، تاریخ‌ها، کاربران، تراکنش‌ها، سوابق تأیید، ممیزی و سایر اطلاعات در D1 باقی می‌مانند تا گزارش‌های سالانه و چندساله آنلاین همچنان قابل تهیه باشند.
- تصاویر آواتار کاربران پاک نمی‌شوند.
- هر فایل ماهانه را نگه دارید؛ تصاویر ماه‌های قبلی در فایل‌های پشتیبان قبلی قرار دارند. ابزار دسکتاپ برای خواندن و تجمیع آرشیوها مرحله بعدی توسعه است.
- تهیه فایل روی رایانه به دانلود توسط مدیر نیاز دارد؛ زمان‌بندی خودکار Worker نمی‌تواند بدون حضور مرورگر فایل را مستقیماً روی دسکتاپ ذخیره کند.
